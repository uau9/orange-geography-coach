# 章节 PPT 整合方案

## 当前产物

“宇宙中的地球及运动”拆为四册，每册 15 页：

1. 宇宙环境与地球宜居；
2. 地球自转、时间与日期；
3. 地球公转与太阳运动；
4. 月相、日月食与潮汐。

四册覆盖当前 16 个已建成实验室。每册统一采用“考点地图—推理链—实验室—即时诊断—两道高考题—综合挑战—延迟复测”结构。真题页和答案页分离；改写只用于压缩材料、转写图示信息或重排选项，并在页眉和备注中记录来源。

机器可读目录位于 data/presentation_catalog.json。deck_id、slide_id、lab_id 和 question_id 均保持稳定；仅修改文字或视觉时不改变这些编号。

## 推荐接入顺序

### 第一阶段：项目内提供章节资料入口

- 首页仍保持现有项目目录，不新增四张大型卡片；
- 在“宇宙中的地球及运动”章节详情页增加一个“讲练测资料”入口；
- 展示四册标题、适用考点、关联实验室和 PPTX 下载按钮；
- 从 data/presentation_catalog.json 读取目录，不把文件名和实验编号写死在 app.js；
- 记录下载或打开行为，但不把“打开 PPT”记为掌握。

这一阶段改动最小，PPTX 可离线下载并在 iPad 的 PowerPoint、Keynote 或 WPS 中使用。

### 第二阶段：把每页转为项目原生学习卡

- 构建时导出每页 WebP 预览图和结构化文字 JSON；
- 项目默认显示 WebP/HTML 学习卡，PPTX 仍作为教师和家长可编辑源文件；
- 实验页根据 lab_id 显示“进入实验室”按钮；
- 真题页先保存选择与理由，再允许打开对应答案页；
- 答案页保存学生自我订正、候选 error_tag 和家长确认。

iPad 优先使用 16:9 横屏学习卡，不把完整 PPT 直接嵌入 iframe。这样可以避免大型 Office 文件在 Safari 中加载慢、手势冲突和离线兼容问题。

### 第三阶段：形成学习记录闭环

建议新增独立的 presentation_attempt 记录版本，最少包含：

- deck_id、deck_version、slide_id；
- question_id 或 lab_id；
- opened_at、answered_at；
- 学生原始答案与原始理由；
- AI 候选错因、家长确认状态、教师复核标记；
- retest_due_at、复测题编号和复测结果。

页面浏览进度只说明“接触过内容”。掌握状态仍由独立作答、解释和延迟复测共同决定。

## 内容维护约定

- PPT 内容源、页面目录和项目题目数据应共享稳定编号；
- 更新真题文字或答案时，先核对来源，再提升 deck.version；
- 页面新增、删除或调序时同步更新 slide_count 和 slides；
- 修改目录结构时新增 schema 版本，不静默破坏旧学习记录；
- 发布前检查 PPT 页数、来源备注、题目—答案配对、实验室编号和 iPad 横屏效果。

## 下一步实现边界

本轮只交付 PPT、目录和整合设计，不改变首页、路由或学习记录格式。正式接入项目属于行为变化，应单独实施并完成：

1. 内容和 schema 校验；
2. 学生未作答前不可访问答案；
3. iPad 横竖屏及手机触控验收；
4. 本地静态服务器与 GitHub Pages 验收；
5. 学习档案导出能保留 deck、slide、lab、question 和复测信息。
